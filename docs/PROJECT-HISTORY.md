# BDO Suite 개발 역사

정리일: **2026-11-06, 한국 시간** · 이 문서의 정리 기준판: **v1.0.0**. 이후 최신 패치는 [변경 이력](../CHANGELOG.md)을 확인합니다.

이 프로젝트는 기존 검은사막 물교 계산기를 바탕으로, 실제 플레이의 반복 작업을 줄이는 개인 도구를 만드는 과정에서 시작했습니다. 교환 경로를 계산하는 기능에 캡처·인식·검수·저장을 연결했고, 이후 연금과 제작노트까지 별도의 작업실로 확장했습니다.

이 문서는 완성된 기능만 나열하는 연혁보다 **어떤 불편을 발견했고, 어떤 선택을 거쳐 현재 방식에 도달했는지**를 기록합니다. 이전 코드 전체를 처음부터 독자 개발한 것으로 표현하지 않습니다.

## 버전과 근거를 읽는 방법

- `v0.x`는 **이번 정리에서 사후 부여한 발전 단계 번호**입니다. 해당 시점에 그 번호로 실제 출시·태그한 사실을 뜻하지 않습니다.
- 현재 `v1.0.0`은 기존 파일의 임의 버전 번호를 승계하지 않고, 현 구현을 앞으로 유지보수할 기준판으로 다시 정의한 것입니다. 작은 후속 수정부터 [버전 운영 지침](agents/VERSIONING.md)과 [변경 이력](../CHANGELOG.md)을 따릅니다.
- 날짜 범위는 Git 커밋 기록 기준입니다. 대화에서만 확인되는 Git 이전 작업에는 정확한 날짜를 추측해 붙이지 않았습니다.
- 첫 확인 가능한 커밋은 `f13b8e1`(2026-09-28)입니다. 구현 조사 당시 HEAD는 `3fb4c53`(2026-11-05)이었으며, 마지막 v1.0.0에는 2026-11-06에 앱에 반영한 수정도 포함합니다. 당시 미커밋이던 보완은 아래 작업별 커밋으로 정리했습니다.
- 실제 적용, 실험·검토, 이후 계획을 구분합니다. 테스트 통과를 실제 게임 인식 정확도나 모든 상황의 최적 경로 보장으로 확대하지 않습니다.

현재 등록된 Git 워크트리는 `D:/BDO`의 `main` 하나입니다. 과거 워크트리 이름은 대화와 보존 커밋의 맥락으로 사용했으며, 없는 작업 폴더를 현재 실행 근거로 삼지 않았습니다. Git 원격은 현재 `kwangs7243/JK_BDO`를 가리킵니다. 예전 `BDOBarterDev`, `_dev` 이름은 개발·설치 파일 분리 과정의 흔적입니다.

## Git 이전 · 출발점

사용자 대화에 따르면 스케줄 생성 알고리즘은 기존 원본에서 가져왔고, 인식·저장·실사용 편의는 이후 요구에 맞춰 발전시켰습니다. 초기 관심사는 물교 목록을 옮겨 적는 일, 재고를 맞추는 일, 만들어진 항로를 게임에서 따라가는 일을 줄이는 것이었습니다.

Git의 첫 스냅샷부터 원본 HTML, 계산 결과 비교 자료, 창고 기준 이미지, Flask/SQLite 앱과 패키징이 이미 존재합니다. 따라서 9월 28일을 최초 아이디어·전체 개발 시작일로 단정할 수는 없습니다. Git 이전 각 수정의 날짜와 최초 원작자·외부 저장소는 현재 자료만으로 확정하지 않습니다.

근거: 이 대화의 원본 알고리즘 출처 설명, [첫 커밋의 개발 안내](https://github.com/kwangs7243/JK_BDO/blob/f13b8e1/_dev/README.md), [초기 스냅샷](https://github.com/kwangs7243/JK_BDO/commit/f13b8e1).

## v0.3.0 · OCR의 철자보다 최종 교환 정보를 바로잡다

섬과 물품에는 이미 마스터가 있다는 점을 활용했습니다. OCR이 이름을 완벽히 읽는 것을 목표로 하기보다, 원문을 보존하면서 마스터의 올바른 이름으로 보정하고 최종 교환 행을 만드는 구조로 발전했습니다.

여러 캡처의 중복·충돌을 정리하고, 요구 수량·획득 수량·남은 횟수 같은 변동 값은 따로 확인할 수 있도록 했습니다. 원본 행 이미지와 검수 사유를 함께 보여주고, 검수 결과를 회차에 적용하는 흐름이 연결됐습니다. 읽지 못한 숫자를 실제 0으로 채우거나 미검수 후보를 정답으로 간주하지 않는 경계가 중요해졌습니다.

이 단계에서 만들어진 모든 master adapter·실험용 평가 경로가 현재 UI에 그대로 남아 있는 것은 아닙니다. 현재는 최종 보정·검수 흐름과 근거 보존이 제품 계약의 중심입니다.

## v0.6.0 · 읽어 본 모양을 다시 OCR하지 않기

영역 크기를 유지하고 위치만 옮기는 방식으로 입력의 변동을 줄였습니다. 이어서 섬·품목·숫자 등 필요한 필드를 잘라 검증된 이미지 특징과 먼저 대조하고, 맞는 자료가 없을 때 OCR을 사용하는 경로를 만들었습니다.

핵심 선택은 외부 AI 서비스를 추가하는 것보다 실제 사용에서 나온 표본을 재사용하는 것이었습니다. 다만 전체 회차의 결과를 이전 회차 값으로 덮어쓰는 것은 아닙니다. 재사용 대상은 같은 입력 모양의 판독 근거이고, 현재 수량과 교환 정보는 현재 캡처에서 나옵니다.

오프라인 표본 평가와 구현 인계 문서를 마련했고, 경유지 입력에는 섬·재료 자동완성을 추가했습니다. 이때의 실험·ML 후보 평가를 현재 제품이 자동 학습하는 신경망으로 소개하지 않습니다.

## v0.6.1 · 표본 수보다 올바른 적용 범위

## v0.9.0 · 폰트 변경이 드러낸 의존성

게임 폰트를 바꾸자 기존 이름·숫자 모양 대조의 강점이 약해졌습니다. 특히 숫자를 정해진 모양으로 판독하던 창고에서 문제가 크게 드러났습니다. 사용자 대화에는 검수량 증가, 맞은 이름을 다시 묻는 일, 숫자 오답 자동 통과에 대한 지적이 반복됩니다. 기존 표본 수만 늘린다고 서로 다른 폰트가 동일한 자료가 되지는 않았습니다.

이 시기에는 아이콘으로 품목을 식별하고, 숫자에 neural OCR을 도입하며, 마스터에 맞출 수 있는 이름을 보정하는 방식으로 대응했습니다. 창고 숫자 OCR의 패키지 누락도 수정했습니다. 자동 제외 품목은 코드에서 요청마다 바꾸는 대신 사용자가 설정할 수 있게 했습니다.

이 대응만으로 모든 문제가 끝난 것은 아닙니다. 이후 다시 원본 표본과 숫자 원형·독립 평가를 우선하는 체계로 정리했습니다. 폰트 변경 전후의 체감·검수 이력은 비교 동기이며 동일 조건의 전체 정확도 수치로 환산하지 않습니다.

중앙 연성진에는 완성품을 두고 제작 시작은 아래에 배치했습니다. 4개·5개 재료의 연결과 수량을 읽을 수 있게 구성했으며 기존 목표 중심 UI의 미사용 코드는 정리했습니다. 호환 데이터와 제작 원장은 유지합니다.

아이콘이 없던 물교 품목의 로컬 자산을 채웠습니다. 마지막 수정에서는 **교역 모드를 쾌속·균형과 같은 상단 행**으로 꺼내 자주 쓰는 조작의 접근성을 높였습니다. 항해 본문 안에 별도 설정 영역을 추가하지 않았습니다.
