# 내해 배차 보완 및 20~30회차 후속 점검

2026-11-04 적용. 향후 스케줄 개선 지시를 받으면 이 문서를 먼저 읽는다.

정식 작업 기준은 `D:/BDO`의 `main`이며, 설치 앱에는 검증한 `routing.js`·`scheduler.js` 두 frontend 자산을 반영하고 재시작했다. 미채택 정책 비교 도구는 별도 `codex/scheduler-plan-experiments` 브랜치에 보존하며 운영 코드에 합치지 않는다. 개인 회차 입력·실험 결과·설치 백업은 Git 밖에 보관한다. 후속 작업 전 메인과 설치 자산의 일치 여부를 확인한다.

## 승인 범위

- 교환 대상·원본 행별 횟수·5단 묶음·목표 재고·우선순위·교섭 단가 유지.
- 6·7단이 포함된 출항은 전체 경로를 보완 대상에서 제외. 7단 재출항과 지역 순서 변경 없음.
- 기존 권역 배차를 먼저 생성한 후, 내해 일반 출항 내부 순서 개선과 두 출항의 통째 병합만 수행.
- 대양/고정 까주 본대는 병합하지 않고, 순서 보완도 마지막 고정 노드 뒤의 귀환 구간만 허용.

## 구현

`barter/frontend/js/domain/routing.js`의 `improveLocalDepartureRoutes()`를 `scheduler.js`에서 두 모드 생성 후 호출한다. 원본 계획을 직접 수정하지 않고 후보를 검산한다.

- 원본 행의 교환 내용·횟수, 총 교섭력, 출항 수·전체 예상시간 비증가 확인.
- 창고 출발 재고·배 위 재료·중간 무게·체인 관계를 전체 출항 순서로 재계산.
- 합병한 출항의 적재/시간/교섭력/체인 표시를 다시 계산한다.
- 각 모드 최대 1,600회 후보 평가, 순서 개선/병합 각각 최대 3회 반복. 전역 최적 보장은 없음.
- 후보가 제약에 실패하거나 개선되지 않으면 기존안 유지. 예외 시 원본 계획 반환.
- 기존 저장 스케줄은 자동 재생성하지 않는다. 다음 생성부터 적용한다.

## 데이터 수집

기존 자동 기록을 유지한다. 새 스케줄 생성 후 정상 회차 저장 시 `schedule_generation`에 입력 재고·목록·설정·교섭력·쾌속/균형 최초 결과를 저장한다. 별도 저장 슬롯 클릭 불필요. 같은 입력/엔진 중복 제거, 수동 편집/복원은 새 생성으로 취급하지 않는다. 현재 제한은 30회차/회차당 최신 5개 입력/25MiB다. 재계산이 많은 회차는 최초 상태가 밀릴 수 있으므로 내보낼 때 상태·시점을 구분한다.

## 다음 점검 절차

1. 실제 설치 버전과 소스·엔진 해시, 기록 건수/서로 다른 갱신 수부터 확인한다. 운영 DB를 쓰거나 스케줄을 대신 생성하지 않는다.
2. `python -B -m barter.tools.schedule_cases --database <실제DB> --out <외부새JSON>`으로 읽기 전용 내보내기. 입력/원본 기록을 수정하지 않는다.
3. 같은 갱신의 시작/중간 상태는 같은 평가군에 둔다. 20~30회차 중 일부는 조정에 사용하지 않는 독립 검증군으로 보존한다.
4. 기록 provenance의 엔진 해시를 확인하고 현재 보완 전/후에 같은 입력·설정·시간 모델을 적용한다. 오래된 백업의 당시 엔진 성적이라고 표현하지 않는다.
5. 행별 횟수·재고·교섭력·7단 본대 경로가 동일한지 검사한다. 출항/시간 감소와 계산 비용, 실패·원본 유지 건수를 별도 집계한다.
6. 특정 새 규칙을 모든 회차에 강제하지 않는다. 권역 전체 삭제, 5단 우선순위 완화, 재고 배분 변경, 7단 재출항은 이번 개선에 포함되지 않았으며 임의로 추가하지 않는다.

범위 검증은 `local_app/tests/local_route_refinement.mjs`와 관련 출항 인과/스케줄 검사로 충분히 시작한다. 전체 OCR·연금 회귀를 습관적으로 실행하지 않는다. 저장 이미지나 합성 경계조건을 실제 게임 실사로 보고하지 않는다.

## 이번 검증 결과

과거 입력 13개 중 11개 생성 가능, 원래 교섭 부족인 2개는 동일하게 보류됐다. 22개 모드별 비교에서 11개 예상시간 감소·11개 동일, 행별 교환 횟수·획득·소모·기말 재고·총 교섭력과 7단 본대 경로는 동일했다. 최근 입력은 6→5출항, 약5분34초 감소했다. 더 느린 과적 병합의 거부 검사, foundation·7단 목표소비·출항 인과 검사를 통과했다. 설치 자산 응답 해시·health·모든 DB 테이블과ROI 보존을 확인했다. 실제 게임 실사는 미실행이다.
